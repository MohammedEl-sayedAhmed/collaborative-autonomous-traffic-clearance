Reading this dashboard

One car (the agent) is learning a habit: when an ambulance comes up behind it, what should it do — speed up, slow down, or change lane — so the ambulance can get past quickly? It learns by trial and error over many attempts. This dashboard shows that learning happen, and lets you compare runs as you improve the code.

The words on the screen

RLReinforcement learning — learning by trial and error: try something, see the reward, do more of what worked.
AgentThe learner — the racecar that decides how to move aside.
EnvironmentThe world it acts in — the Gazebo simulation with the road, the agent car, and the ambulance.
EpisodeOne complete attempt, from the start of a scenario until it ends. Learning happens across many episodes.
StepOne decision inside an episode. An episode is many steps.
StateWhat the agent “sees” when deciding: its own speed & lane, the ambulance’s speed & lane, and the gap between them.
ActionWhat it can do at a step: speed up, keep speed, slow down, or change lane.
RewardThe score for an action. Shaped so the agent is rewarded when the ambulance keeps accelerating (path clearing) and penalized when it must slow down. Rewards are ≤ 0, so closer to 0 is better.
PolicyThe learned strategy: “in this state, do that action.”
Q-learningThe method used: keep a big table of “how good is each action in each state.”
Q-tableThat table (saved as Q_TABLE.npy). Training fills it in and sharpens the numbers.
Epsilon (ε)How much the agent explores (tries random things) vs exploits (uses what it learned). Starts high, decays low.
OutcomeWhy an episode ended (see the outcomes chart).

How to read each panel

Cumulative reward per episode — the learning curve. Rewards are negative, so higher / closer to 0 is better. A rising line means it’s learning. Use smooth to see the trend through the noise.

Epsilon per episode — explore-vs-exploit, decaying over time. If it stays high and flat, the agent never settles (train longer / decay faster).

Steps per episode — how long each attempt took. Usually drops as the policy improves.

Episode outcomes — why episodes ended: ambulance reached goal (success), agent reached goal, max time, sim died. More green = better.

Run comparison (table) — per run: git commit, episodes, mean / final / best reward, and success rate (% of episodes the ambulance got through). This is where you read off “did my change help?”

Live tile — while training, shows the current episode/step/reward/ε in real time; a LIVE badge marks a run whose heartbeat is fresh.

How to navigate

Click a run (or its checkbox) to show/hide it. Select two or more to overlay and compare. Use all / none / live to select quickly, smooth + the slider to average the curves, and pause to stop the 2-second auto-refresh. Every run is saved and stays available to compare later.

What “good” looks like

Reward curve rising toward 0, epsilon decaying, steps decreasing, and the outcomes bar turning greener — and, when comparing, your improved run sits above the baseline with a higher success rate.

Note: the shipped RL is a proof-of-concept (few episodes, lane-changes disabled in code, fixed start). The dashboard is built to make those limits visible and measure the effect as you improve the RL and the environment.
